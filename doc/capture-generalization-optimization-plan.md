# Dano 优化方案（最终版）

**目标一句话**：录一遍页面 → 引擎读懂任意业务、任意页面 → 产出 API 形式的业务 skill → 另一个前端项目直接调用。

产物金标准：`console-plugin-cdp-bug-pending-review.zip`（SKILL.md + reference.md + scripts/，脚本直调业务 API、每个写操作配自检）。

---

## 核心原则：理解发生在当下，不做录后验尸

两个难度完全不同的问题：

- **难的问题（旧代码的路线，放弃）**：录制结束后，面对一堆页面、控件、请求、响应，事后离线推断业务目标、接口角色、能力边界、字段语义、接口关系——因果已经丢失，只剩时间戳相关性；
- **简单的问题（参考 zip 的实际生产方式，采用）**：目标是人事先说清的、分支是人亲自选的、模型边看操作边看 Network、疑问当场消除、结果当场验证，验证通过才固化成脚本和 skill。最难的不确定性没有进入推断环节，是被流程消掉的。

```
泛化性 = 模型的世界知识（读懂任意系统的 API 语义）+ 目标由人输入（不推断）
可靠性 = 机器验证回路（每个结论配可执行验证，验证不过不采纳）
```

现有数千行启发式规则降级为候选生成（省 token），不再决定结论。

---

## 完整流程（模型全程参与）

```
阶段0  目标输入(录制前,10秒)
       操作人一句话:"录一个改缺陷状态为待评审的技能"
       【模型】解析为结构化 RecordedGoal ── 最难的"推断业务目标"变成输入
          │
          ▼
阶段1  录制会话(人操作一遍,模型全程在场)
       Playwright: 语义步骤+全量网络拦截+screencast ──实时流(脱敏)──▶【模型】
         · 因果对齐: 点"提交"↔紧随的POST=提交请求; 开下拉↔紧随的GET=选项源
         · 假设构建: 人打的值=用户输入; 响应值进后续请求=依赖链候选(当场标记
           "jobId 疑似派生,≠URL 的 itemId")
         · 当场消歧: 工作台侧栏问一句(人在场,成本零)
         · 攒 Pitfalls 素材: 人选错又改的操作、页面报错
       产出: 因果标注 trace + FlowSpec 初稿(角色/参数来源/依赖链已有初判+证据)
          │  (人离场,此后全程零人工)
          ▼
阶段2  即时验证+自主补采(趁热,agent 无人值守)
       【模型】出验证计划/补采规划 ──▶ 机器执行(代码,模型无权跳过):
         · 读接口直接重放
         · 依赖链扰动重放(换个 itemId 看 jobId 是否联动)
         · 写操作用录制账号真实执行+verify 断言,完了走删除/撤回接口清理
         · agent-browser 补采: 拉全枚举/探完整状态机/给每个写配 verify
           (agent 刚看完人操作一遍,不是盲走陌生页面)
       验证通过 → 写回 FlowSpec(apply_flow_edits 白名单 ops,带验证记录)
       验证失败 → 带错喂回【模型】重试 → 仍不过标 unverified 降级
       (录后推断只剩兜底: 处理会话中漏标的静默请求)
          │
          ▼
       FlowSpec(唯一事实源: steps/links 依赖图/capabilities 对外契约,每条结论带验证记录)
          │
          ▼
阶段3  生成 skill 包(机器闸门,零人工)
       代码生成(保证可执行): client.py + 每能力一脚本(按依赖图先调派生源) + verify_*.py
       【模型】生成(素材已在阶段1/2攒齐): SKILL.md(Steps/Done-when/Branch exit)
         + reference.md(API chain 小节) + Pitfalls
       校验器把关(结构对齐参考 zip) → 不过带错重新生成
          │
          ▼
阶段4  消费(另一个前端项目)
       方式A: 拿包按 SKILL.md 的 SOP 调 scripts/(Prefer=API 脚本;
              纯 API 走不通的能力→Fallback 章节,消费端自己的浏览器执行)
       方式B: 按 FlowCapability 输入/输出 schema 封装,或经 Dano 网关 invoke(保留)
       运行期零模型、零 Dano 依赖
       唯一人工 = 每系统一次性提供账号会话(验证码登录人工登一次)
```

授权原则：**录制账号即授权边界**——能用这个账号录入，agent 用同一账号做的操作就在同一权限半径内，不设夹具、审批等额外边界。验证写留下的记录自动走删除/撤回接口清理，清不掉则保留（与人工录制留下的记录同性质）。

## 六个目标怎么被解决

### 1. 捕获侧泛化 —— 能读取不同的业务、不同的页面

- 捕获层零业务假设：语义 DOM 步骤（label/role 非坐标）+ 全量 trace 无差别入库，对任何系统行为一致；
- 理解主体是模型：世界知识跨系统，规则降级为候选；业务目标由人输入，不推断；
- 引擎去业务硬编码：`ACTION_META`、`std_fields`、`oa_templates`、前端默认 `A-OA`、网关默认 `A-报销` 收敛为按租户加载的业务包数据，缺省为空。

**验收**：两个互不相关系统（若依系 + 非若依系）录制→产出 skill 零改码走通。

### 2. 准确性 —— 参数和依赖判定对

- 因果在现场观察而非事后推断：操作↔请求实时对齐（现有 `trigger_op`/locator 证据已在采，让模型当场消费）；
- 依赖链当场标记 + 机器扰动重放验证（`jobId ≠ itemId` 型链是核心场景）；
- 参数四分类：用户输入 / 会话头 / 页面上下文 / 链式派生（执行期先调源接口）；
- 模糊处录制现场问一句；模型幻觉被验证执行器拦住，未验证结论不进产物。

**验收**：评测集（两系统、10+ 流程、人工标真值）出准确率；派生链场景全对。

### 3. 完整性 —— 整条链路抓全

- 全量 request_facts（现成）+ 补齐 multipart 上传步骤化、写后 settle 时间、错误响应样本；
- agent-browser 自主补采：拉全枚举、探完整状态流转（新建→待解决→待评审）、每个写操作配对 verify 读接口；
- 补采结论走 `apply_flow_edits` 白名单写回。

**验收**：每个写能力都有配对 verify；补采增量全部带验证记录。

### 4. 编排性 —— 产出可编排的多步 SOP

- `FlowCapability` 契约承载编排（保留，它就是对外调用契约）；
- SKILL.md 按金标准由模型生成：Transport 表（Prefer/Fallback）、Steps 带 Done-when、Branch exit（已是目标态则跳步）、Pitfalls（现场素材自动总结）；
- 文档零手写；唯一手写的是一次性元规范（定义合格包 + 校验器）。

**验收**：校验器全绿，结构与参考 zip 同构。

### 5. 最终利用 API 的形式产出 skill

- 自包含包直调目标业务系统：`client.py`（base_url/凭证装配/`http_json`/成功规则/settle）+ 每能力一脚本 + `verify_*.py`；
- 会话：token 环境变量或本地缓存（Dano token 只读端点复用 `token_store`）；
- 现有 `dano_call.py` 网关代理形态保留共存（skillfrontend 继续用）。

**验收**：不启动 Dano 的机器上，凭 token 环境变量跑通「查 → 写 → verify ok」。

### 6. 让另一个前端项目调用

- 直接拿 skill 包按 SOP 调 scripts，或按 capability schema 封装成自己的服务调用；
- 纯 API 走不通的能力（防重放签名等）Fallback-only，如实标注，不影响其余能力。

**验收**：独立于 skillfrontend 的项目在目标系统完成「写操作 + verify ok」闭环。

## 实施顺序

```
① 执行器工具集(重放/扰动/值溯源候选) + 元规范校验器          ← 并行,约 2 周
② 录制会话接入模型(目标输入 + 实时事件流 + 侧栏消歧,
   复用 recording_pi 会话桥)                                  ← 约 1-2 周
③ 人工驾驶验证: 用 Pi/Cursor 会话扮演阶段2的 agent,借①的工具
   把一个真实业务从录制走到 skill 包产出                      ← 架构 go/no-go
④ 固化阶段2为自动 agent(验证计划/补采/带错重试)               ← 约 2-3 周
⑤ export 自包含包渲染 + 引擎去业务硬编码收尾                  ← 约 2 周
⑥ 双系统零改码验收 + 独立前端项目调用闭环
```

复用底座（不重建）：Playwright 录制、request_facts、FlowSpec/FlowLink/FlowCapability、`RecordedGoal`、`apply_flow_edits`、`recording_pi` 会话桥、`token_store`、export 管线。

置信依据：参考 zip 就是按「目标前置 + 现场逆向 + 即时验证 + 固化」生产的（存在性证明）；底座逐个核实存在且基线 1444 测试通过；全案唯一无先例的「无人值守 agent 质量」被③步 go/no-go 兜住，失败损失封顶。
