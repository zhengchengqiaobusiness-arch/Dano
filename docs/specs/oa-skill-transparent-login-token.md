# OA Skill 原包零修改的登录凭据自动接入

本规格修正 Issue #456 中要求修改 Python 请求入口的错误方案。PR #457 的适配版测试不构成本规格的验收证据。本文只定义需求、实现边界和完成标准，不表示功能已经实现。

## Problem Statement

Dano 已能通过 OA 登录，但现有 OA Skill 原包中的 Python 脚本自行构造接口 URL 和认证头，可能使用包内固定或过期的 token。用户需要直接执行这些原包，由 Dano 在运行时判断请求目标，并对匹配 OA 域名和端口的请求使用发起操作的当前登录凭据。

用户不接受修改 Skill 源码、配置文件、导入语句或 HTTP 调用方式，也不接受另写适配版作为交付和验收对象。

## Solution

在 Dano 受控 Python 执行期间提供透明请求处理能力。脚本仍按原来的方式发请求；请求目标域名和有效端口与配置的 OA 业务接口目标一致，且发起本次 Assistant Turn 的 Dano Login Session 有效时，实际出站请求使用该会话的 Provider Credential，覆盖脚本原有的 Authorization 头。

该能力由 Dano 运行环境提供，用户不需要安装到 Skill 内部、修改原包、手填当前登录 token 或在每次调用时选择身份。原包自带的业务域名继续用于匹配判断；不得为了通过验收而把它改成本地代理地址或相对路径。

目标不匹配时，不注入 Dano 凭据，保留普通请求行为。没有 Dano 登录身份时，不提供 Dano 凭据；本功能不承诺使原包自带的独立凭据失效。

## User Stories

1. As an OA 用户, I want 原包直接运行且文件内容不变, so that 无需维护 Dano 专用 Skill 分支。
2. As an OA 用户, I want 匹配 OA 域名和端口的请求使用当前登录 token, so that 查询以本次登录身份执行。
3. As an OA 用户, I want 覆盖脚本已有的旧 token, so that 包内固定凭据不会决定实际请求身份。
4. As an OA 用户, I want 脚本未设置认证头时也能自动认证, so that 不依赖 Skill 主动接入 Dano 客户端。
5. As an OA 用户, I want 原有 URL、查询参数和业务处理保持有效, so that 原包功能不因认证接入而改变。
6. As an OA 用户, I want 一次脚本的多个 OA 请求均经过相同处理, so that 不出现部分接口遗漏认证。
7. As an 非 OA Skill 用户, I want 其他目标的请求不被改写身份, so that 普通网络能力保持原有行为。
8. As an 多用户部署维护者, I want 并发执行严格使用各自会话的凭据, so that 不发生串号。
9. As an 同一 User 多次登录的用户, I want 操作绑定发起它的 Login Session, so that 其他登录不会替换本次身份。
10. As an OA 用户, I want 取消、登出或会话失效后停止使用该会话凭据, so that 遗留执行不能继续借用登录权限。
11. As an OA 用户, I want 凭据可刷新时沿用既有刷新流程, so that 无需把刷新逻辑放进 Skill。
12. As an 维护者, I want 认证失败时不退回包内 token, so that 不会悄悄换成另一个身份。
13. As an 维护者, I want 重定向和相似域名不能获得 OA token, so that 当前登录凭据不会发往其他目标。
14. As an 验收者, I want 用用户指定原包进行真实 OA doctor 和 query 验收, so that 结果直接证明需求。
15. As an 验收者, I want 查看原包完整性、接收端鉴权验证与原始状态摘要, so that 不依赖模型自然语言判断成功。
16. As an 部署维护者, I want 在本地真实容器中完成验收与清理, so that 不必部署生产来证明功能。

## Implementation Decisions

### 原包不变与执行边界

- 不修改原包内任何原有文件；不修改源码、配置、依赖声明、导入语句、URL 或 token 配置，不生成替代业务脚本。解压前后及执行后的原有文件必须逐文件哈希一致。
- 接入放在 Dano 管理的执行环境和请求转发边界。可选择运行时加载或受限转发等机制，但不得要求 Skill 主动调用新增客户端。机制选型必须先用原包的真实 HTTP 调用方式证明可行。
- 必须支持指定原包的 Python 标准库 HTTP 请求和全部四个业务接口。对其他 Python HTTP 客户端明确记录实际覆盖范围，不得用只支持改写后的客户端宣称任意原包均可用。
- 保留 Heimdall、User Folder 和 Runtime Workspace 隔离。不得全局修改 Python 安装或把进程级共享 token 作为实现。
- 如果原包在发请求前因配置占位值等业务检查自行退出，必须如实记录该阻塞，不能偷偷改包或绕过检查后算通过。原包已有 CLI 参数可以正常使用，但不得手工传入当前登录 token，也不得修改目标域名规避匹配。

### 请求目标与认证规则

- OA 匹配目标来自服务端明确配置的 OA 业务接口地址，部署时与 OA 页面地址保持一致。不从 OAuth token/identity 端点、脚本提交的身份字段或 DNS 解析结果推断目标。
- 使用标准 URL 解析，按规范化 hostname 和有效端口精确匹配。省略端口按协议默认端口解释；禁止子串、域名后缀、同 IP、任意子域名或通配端口匹配。协议须符合配置地址的协议，不进行隐式协议改写或降级。
- 每次实际出站前都做目标判断，包括重定向后的目标。路径不参与身份选择，路径和查询参数仍由原脚本决定。
- 匹配目标且会话有效：在服务端读取该 Login Session 的 Provider Credential，移除调用者重复或大小写变体的 Authorization 头，发送唯一的当前登录 Bearer 认证头。原有 token 不能覆盖它；认证接管后失败也不能回退到原有 token。
- 本规格覆盖 Authorization Bearer 认证，不自动猜测或改写业务参数中的自定义 token、签名或 Cookie 认证协议。
- 不匹配目标：不添加 Dano token，保留原有业务请求。由 OA 请求重定向至其他域名、端口或协议时，必须移除已注入的 Dano 认证，不得恢复原认证头来静默换身份；也可以按既有安全合同明确拒绝该跳转。
- 无有效登录：不注入 Dano 凭据、不读取其他会话凭据。新匿名执行的原生请求可以继续按原包行为处理；因此原包自带 token 的成功或失败不能单独证明 Dano 登录隔离。
- 已接管的执行在登出、取消或绑定失效后，后续 OA 请求明确拒绝，不能改绑到新登录或退回原包 token。不要求撤回已经提交给 OA 的业务副作用。

### 身份、凭据与错误

- 复用 Credential Broker 和 OAuth Provider Adapter，绑定发起 Assistant Turn 的 Dano Login Session；不按 User 找“最近一次登录”，不接受模型或脚本指定其他会话身份。
- Provider Credential 继续归单个 Login Session 所有。刷新复用现有协调流程，凭据轮换不改变身份归属；刷新失败明确报告认证失败。
- 当前 OA access/refresh token 不写入原包、命令参数、共享环境变量、模型上下文或日志。运行环境若使用调用能力，须限制到本次执行和固定会话，结束后释放。
- 不关闭 TLS 校验，不通过开放公网代理实现透明接入。HTTP-only OA 使用服务端显式配置的现有协议，不借本功能扩大允许目标。
- 保留请求方法、路径、查询、业务头和请求体的语义，向脚本返回兼容的 HTTP 状态、响应头、响应体和异常。区分认证错误、网络错误和业务错误；不增加可能重复业务写入的通用自动重试。
- 保持现有 provider_request 合同及 ADR 关于 Dano Login Session、Provider Credential 和独立 Provider Browser Session 的边界。原包中既有秘密不因本任务获得公开发布授权。

## Testing Decisions

### 主要测试边界

主要边界为“绑定 Assistant Turn 的受控 Python 执行 → 实际接收 HTTP 请求的测试 OA”。复用现有 Broker、OAuth 会话、并发与 Heimdall 测试设施；测试可观察的出站身份、请求、返回和生命周期，而不是某种内部拦截类或通信文件名。

测试服务器使用人工凭据，直接断言收到的 Authorization 值。真实 OA 验收使用服务端脱敏关联证明，不暴露真实 token。假 OA 回归不能替代真实 OA 验收。

### 自动化验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 已登录，目标匹配，原请求有旧 token | 接收端收到当前会话测试 token；旧 token 未出站 |
| 已登录，目标匹配，原请求无认证头 | 接收端收到当前会话测试 token |
| 已登录，原请求包含重复或大小写不同的认证头 | 接收端仅收到一个当前会话认证头 |
| 相同 hostname、不同端口 | 不注入 Dano token；普通请求不被错误接管 |
| 不同 hostname、相同 IP 或相似后缀 | 不注入 Dano token |
| 默认端口与显式默认端口、hostname 大小写 | 按标准化结果匹配，避免字符串比较误判 |
| 协议不符合配置或重定向跨目标 | Dano token 不发送到新目标；阻止或安全处理跳转 |
| 未登录的新执行 | 接收端没有 Dano token；原请求的独立凭据行为不被误报为 Dano 登录成功 |
| 多 User 并发、同 User 不同 Login Session、排队及后续 Turn | 接收端身份与发起执行的会话逐一对应 |
| 接管后登出、取消、执行结束或会话失效 | 后续 OA 请求拒绝，旧能力不可复用，不回退包内 token |
| token 刷新成功或失败 | 使用同一会话的新凭据或明确认证失败，不切换身份 |
| GET 查询、POST JSON、多请求、非 OA 请求 | 除规定的认证处理外，业务语义和返回兼容 |
| 错误与输出路径 | 人工 Dano token 不出现在脚本输出、模型消息、错误或持久化审计中 |

### 指定原包的真实 OA 完成门槛

以下全部满足才可称本需求通过：

1. **原包来源和完整性**：使用用户提供的 `pointlion-todo-query-token-inline.zip`，记录 ZIP SHA-256 和全部原有文件的相对路径、SHA-256 清单；安装后、执行前后逐一相同。测试材料安全保管，不将含凭据原包公开提交。包内源码、配置或请求入口存在修改即不通过。
2. **真实执行环境**：在本地按正式 Podman/Compose 路径部署待验收版本，使用隔离运行数据。通过内置 Browser 完成真实 OA 登录，再由该登录会话的 Assistant Turn 调用实际受控 bash 执行原包。宿主机单跑、模拟 OA、模型直接调用 provider_request 或适配版脚本均不能替代。
3. **目标确实匹配**：记录脱敏后的实际出站目标匹配结果，包括 hostname、有效端口和协议是否等于服务端配置。不能只记录相对路径，不能以 DNS 同 IP 作为依据，不能为测试修改原包中的业务域名。
4. **证明覆盖的是当前登录凭据**：关联同一次脚本执行、发起 Turn、Login Session、凭据解析和实际出站请求。服务端在最终发送处记录会话绑定验证与最终认证头等于该会话解析凭据的布尔结果；结合接收端人工凭据覆盖测试，排除包内旧 token 生效的替代解释。不得仅以 HTTP 200、模型总结或由请求成功推导出的 loginSessionBound 字段证明身份。若能取得 OA 侧脱敏身份/审计证据则一并保留；未取得时明确说明证据来自 Dano 出站边界，不声称做了 OA 服务端独立比对。
5. **doctor 成功**：执行原包 doctor，进程退出码 0。分类、流程定义、系统字典、待办分页四个真实 GET 接口均为 HTTP 200、业务 code 0；任何漏执行、认证失败、非零退出或业务错误均不通过。
6. **query 成功**：执行原包 query，页码 1、每页 1 条，进程退出码 0。由程序直接解析原始响应并记录 list 长度和 total，不从模型总结抄取；list 为有效列表，total 为有效非负总数。空列表且 total=0 可以通过，不固定 OA 实时数量。
7. **真实身份生命周期检查**：验证登出后不能继续取得本次 Dano 凭据。若原包自带 token 仍能单独访问 OA，报告为原包独立认证行为；不得把它当成当前登录凭据仍可用或借此省略接管后失效测试。
8. **证据留存**：保留可独立审阅的结构化脱敏记录：版本/镜像标识、原包完整性清单、实际脚本命令与退出码、四个接口状态、最终出站身份关联验证、query 原始响应解析出的数量、浏览器登录和执行截图。清理容器前导出验证记录；摘要必须标明直接观测与推论，缺少记录时不能事后用模型口述补成证据。真实 token、Cookie、原始身份标识和待办明细不进入公共记录。
9. **只读与收尾**：真实 OA 只运行查询，不审批或修改业务。需要临时 OAuth 回调变更时只在明确授权范围内执行，保留原配置，完成后移除本次新增项；清理测试凭据、证书信任、容器和运行目录，保留脱敏证据。

执行项目类型/Svelte 检查、相关回归、全量测试和构建；按部署规范完成文本、模型触发 bash 与图片读取检查。分别报告“原包 OA 凭据接入”与其他部署门槛，不把某个无关检查的成功或失败当作原包请求身份的证明。

## Out of Scope

- 修改或迁移 Skill 到新增 Python SDK、重写业务脚本、用模型代发原包请求。
- 修改原包 URL/token 配置来使透明接入测试通过。
- 全机器流量接管、任意语言和原生二进制的通用透明代理、恶意代码绕过所有隔离的防御平台。
- 自定义 token 查询参数、签名或 Cookie 协议的自动转换。
- OA 与 Dano 全局登录/登出同步、修改 OA 权限模型或凭据协议。
- 自动生产部署，以及未经授权变更 OA 客户端或公开原包内的秘密。

## Further Notes

旧 Spec 要求“适配脚本请求入口”并将“拦截未适配脚本”列为范围外，与用户要求相反，相关内容由本规格替代。此前适配版 doctor/query 成功只证明另一条调用链可用，不能延续为本规格的完成状态。实现应先证明指定原包零修改可运行和最终出站认证覆盖，再扩展回归；不能先修改原包以迁就机制。

未登录新执行采用“不注入 Dano 凭据、保留原包普通行为”的规则；这与“禁止所有匿名 OA 请求”是不同功能，后者不在本次需求中推定增加。已接管执行失效后则必须拒绝，避免静默回退身份。
