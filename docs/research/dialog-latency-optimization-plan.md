# 对话首字延迟局部优化与前后对照方案

日期：2026-11-06。状态：讨论稿，尚未实施。

## 目标与边界

在现有 https://1.15.173.22/ 测试环境，减少模型请求前的等待，保持自动记忆召回、授权隔离、收集边界及业务流程行为。先取得优化前六次基线，完成局部优化和验证后更新现有环境，再按相同条件测试六次，报告逐次和平均首字时间。

不改整体架构，不调整模型、提示词、记忆开关、召回超时或召回质量参数。既往两次复测仅作背景，不混入新的六次基线。这里将“再同时测试”理解为采用同一套条件和用例复测；六次串行执行，不混入并发排队因素。

## 实施范围

1. 取消贯穿：在 pi-openviking 自动召回路径，将同一 deadline/signal 传递到状态锁等待及底层检索 HTTP；核查 SDK 的实际接口，选用其支持的取消机制，不以外层 Promise.race 代替底层取消。保留身份校验、请求隔离和调用间取消隔离。
2. 合并重复事务：将会话路径登记与本轮自动收集 begin 合并为一次原子事务。保留路径安全检查、会话不得重绑定、授权版本检查、用户消息追加前的收集边界及持久化保证。继续保留 fsync，不把 begin 异步挪到回答之后。
3. 仅限诊断的分段耗时：锁等待、状态加载与校验、持久化、收集登记/begin、检索、token 计数、上下文准备及 provider_request。只记录关联 ID、阶段、耗时和结果类别，不记录正文、记忆内容或凭据。基线和优化后须采用相同诊断口径；若基线版本无法提供细分阶段，明确缺项，不用改后数据反推改前耗时。

修改主要在 pi-openviking 插件，Dano 只做必要版本接入和诊断适配。先确认插件源码与部署版本的对应关系。是否能加速本次前置等待由实测决定，不预设提升百分比。

## 六次基线与复测矩阵

每次使用同一登录测试账号的新会话；输入完全一致，顺序一致，前一轮正常结束或取消待填表单后才执行下一轮。取消等待单只用于结束首字用例，不额外提交业务记录。

| 次数 | 输入 | 用途 |
|---|---|---|
| 1 | 只回复“收到”，无需办理业务。 | 简单回复 A |
| 2 | 请假 | 请假入口 A |
| 3 | 申请公章 | 公章入口 A |
| 4 | 只回复“收到”，无需办理业务。 | 简单回复 B |
| 5 | 请假 | 请假入口 B |
| 6 | 申请公章 | 公章入口 B |

新会话消除上下文累积差异。账号记忆仍可能随后台任务变化，记录该局限及诊断中的状态版本/任务活动，不清空或回滚用户数据来制造一致性。双方使用同一固定预热步骤（一次不计分的简单回复），等待结束再开始六次计分；不单独给优化版额外预热。

## 计时与证据

主指标：浏览器发送 prompt HTTP 请求，到收到首个非空 assistant text 增量的时间，使用浏览器同一单调时钟。它是首字到达时间，不宣称等于精确屏幕绘制时间。thinking、工具参数、空消息、agent_start 不算首字。

同时记录 HTTP 接收、agent_start、首个 assistant 事件、完整回复/首张表单准备时间、错误和超时；后一指标用于发现只把耗时后移的情况。表单填写和人工确认时间不计入系统耗时。跨主机时间未经校准不作精确阶段差值；服务端分段使用自身单调时钟。

每条保存 run ID、会话 ID、版本/镜像、模型与回答模式、用例、开始时间、各项耗时、结果和采样完整性。分别采样 CPU、内存、swap 活动及服务重启情况。网络事件仅保留脱敏投影，不保存认证头或完整请求正文。

六次全部列出，不挑最快结果、不删慢样本。若无首字、请求失败或采样丢失，标记失败/缺失；平均值只对有效首字样本计算并标明 n/6，不能把失败算作 0。任何补测单独列出，不覆盖原始六次。

## 实施与部署顺序

1. 固定现有环境版本、配置指纹和测试条件，先完成六次基线并保存原始脱敏时序。
2. 根据分段证据核对优化适用性；完成插件局部修改、必要 Dano 接入及针对性回归。
3. 验证：锁等待可取消；检索取消真正终止客户端请求且不影响其他调用；合并事务在重复登记、并发、取消、崩溃恢复和授权撤销下保持语义；记忆保存/召回及表单默认值不退化。
4. 按仓库工作流完成 PR、检查与合并，再更新指定服务器现有部署；记录新旧镜像，保留可回退版本和运行数据。
5. 服务就绪后执行相同预热及相同六次测试。部署后的其他验收独立记录，避免混入性能样本；完成请假、公章完整业务流程回归以及部署要求的浏览器验收。
6. 输出逐次对照、总体平均、每类用例平均及异常说明。清除本轮临时诊断控制，保留脱敏结果和服务运行。
