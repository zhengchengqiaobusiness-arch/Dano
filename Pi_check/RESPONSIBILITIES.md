# 谁负责什么

PI 是唯一语义决策者；旧录制逻辑绝不启动。

最终必须产出能力。现有前端录制页 `skillfrontend` 的 `PageRecorder` 复用：预览始终可点，不锁指针。

| 事项 | 谁改 | 谁判断 |
| --- | --- | --- |
| 启动/关闭浏览器、采证、冻结、存盘、把结果推给现有页面 | 代码 | 无语义。采集可含弹层、表格行、加行按钮等事实，仍不分类 |
| 动作队列串行、人与 PI 共用同一页、协助横幅 | 代码 | 不锁预览，不丢弃人的点击 |
| 证据索引与动作台账（interaction / xhr 摘要，带 actor，无分类） | 代码 | 无语义 |
| 跨页面的调查顺序、能力切分、字段合同、编排规则 | Skill：`skill/RECORDING_CAPABILITY.md`（总入口 + 推断）、`skill/CONTROL_IN_APP_BROWSER.md`（只操作取证） | 模型按 Skill 执行 |
| 这一场有几个能力、哪个请求属于哪个能力 | 不改代码 | 模型 |
| 字段名称、类型、来源、必填、调用方还是系统 | 不改代码 | 模型 |
| 依赖和执行顺序 | 不改代码 | 模型 |
| 何时自动点、何时 assist 请人帮忙 | 不改代码 | 模型 |
| PI 没交能力 | 代码只失败 | 禁止本地编造能力 |
| 页面读不到的信封、重复 capability_id、两个能力共用 execute | 代码拒收，不改写 | 模型按 Skill 重交 |

改识别策略或调查顺序：改 Skill。代码入口只加载 Skill，不得另写一套「立刻点 / 立刻交」口令。  
改采集/传输/与现有页对接：改 `Pi_check` 代码。  
改某一场业务结论：让 PI 重读证据，不要写页面专用规则。
