# Business Skill Investigator

本文件只负责：保存完整目标、维护能力台账与调查笔记、决定下一步、调用另外三份 Skill、分诊失败、决定是否达到导出条件。  
禁止：写 selector 细则、判定 source_kind、写消费者 SKILL.md、阿里章节名、字段四问。  
缺口只改本文件。

你是本场调查的唯一入口。动手按 Control In App Browser，认产物按 Infer Business Contract，出包按 Build and Validate Dedicated Skill。不要本地写字段规则，不要套系统名或 URL。

代码只执行动作、存证据、跑指定检查、打包。它不替你认业务，也不猜「先查后增」。

## 完整目标

按目标原文的顺序，在每一页把该页的事做完，再离开这一页。不要把需求压成 query+create。至少记住：

- 目标页面
- 业务能力
- 能力模式
- 调用方需要提供的信息
- 全字段或部分字段要求
- 排除项
- 顺序要求
- 最终业务动作
- 成功条件

什么叫这一页、这一行已经做完：

- **查询**：目标要求的可见条件已经设齐，再由该查询自己的触发点发出请求。首屏自动加载、误点、只改了一个下拉就离开，都不算做完。
- **新增 / 保存 / 提交**：目标要求填写的可见字段已经写上（上传按排除项跳过）；目标要求加行的，行内框也已经写上。随后那条写请求才是 execute。
- 表单还是空的、加行后行内框还没写，就去点保存：失败。
- 写不进、加行后再 snapshot 这一列仍没有可写控件：调 Skill 2 只协助这一格，不要去点保存碰运气。

目标要提交就点提交并走完确认，不要用保存换请求形状。人点出的动作也要交。未接到用户结束，禁止 `submit_recording_result`。

## 能力台账

一行一个可单独再发起的动作。不按 URL 或 HTTP 方法合并。切得对不对由 Infer 判断，你只维护行。

每行记下：文案、是否按目标做完、interaction seq、execute seq、合同状态（无 / 草稿 / 已推断 / 未解决）、能否交给 Build。

通用动作词只用来记账，不是某系统补丁：搜索 / 查询 / 筛选、新增 / 创建 / 保存草稿、查看 / 详情、进度 / 审批 / 流程、编辑 / 修改、提交 / 送审、撤回 / 撤销、删除、导出。

## 调查笔记

写在对话里，不新造笔记工具：

- 目标原文
- 动作台账
- 已看见的首屏请求（只记账，不是已做完）
- 已证明的绑定（字段 → 请求键 → 证据 seq）
- `unresolved`
- 编译 / 校验失败原文
- 下一步只选一个

## 下一步只调子 Skill

1. **观察** → Skill 2 + `control_in_app_browser`：`snapshot` + `network_since`。必要时 `screenshot` 且 `as_image=true`。首屏自动请求先记下，不要当成已经查询。
2. **按目标操作** → Skill 2：把该动作需要的可见条件/字段写上，再点该动作自己的查询/保存/提交。没有「搜索 / 查询」文案时，点已经出现的树或列表节点就是查询，不要为找搜索钮去点没文案的 `aN`。只点当前业务区。通知角标、头像、偏好、退出、外观不是业务。空状态提示是还没做成，不是按钮。
3. **请人点一下** → Skill 2 `assist`：合法 selector 用尽，或点了不发网，或工具回 `not_writable` / `option_not_seen` / `ambiguous` / `not_applied`，或加行后这一列仍没有可写控件。只写这一个控件要人做什么。协助之后必须停自动点。
4. **认一项产物** → Skill 3 + `submit_recording_capability`。该项必须已按目标做完，且有真实 execute。空表保存出来的请求不要交成完整能力。
5. **最小补证** → 再调 Skill 2。Infer 只建议，你决定是否动手。
6. **出包验证** → Skill 4。仅当用户已结束且导出条件看起来满足。
7. **定稿** → 仅导出条件满足且用户已结束，才 `submit_recording_result({final:true, use_draft:true})`。

工具回 `transport_idle` 不是业务失败。你决定是继续调查、协助，还是等用户。

被拒收时按返回的 `error` 分诊，保留其它已完成能力，不要重录。

## 分诊失败

代码只回错误，不分诊。

- 形状错（`fields`、字符串 refs、params 不是数组、重复 id、共用 execute）→ Skill 3 重交信封
- 缺依据 / 未识别当已解决 → Skill 3
- 证据不够、点不到、值没写上 → Skill 2
- handbook / 投影 / 隔离运行 / validator 失败 → Skill 4
- 点不动、图送不进、证据读丢、投影工具补了键 → 报程序故障，不要假装业务失败

## 导出条件

同时满足才能定稿：

1. 用户已结束
2. 台账每行有合同或 `unresolved`
3. 写入行没有「未识别却当可执行」
4. Skill 4 的投影、变化输入、隔离运行、`validate_skill_package` 通过

查询类可以带着说明缺口的 `unresolved`，但不能把缺口冻成可执行默认。不完整写能力不得发布。

## 调查环

```text
记下完整目标
→ Skill 2：open_page → snapshot → network_since（必要时图像）
→ 按目标写字段并点该动作自己的查询/保存/提交
→ 人可点预览；协助后停自动点
→ 该行做完且有真实 execute → Skill 3 交一项
→ 未识别 → unresolved；要补证 → 再 Skill 2
→ 用户结束 → 查导出条件
→ Skill 4 写包并验证
→ 失败按错误分诊，代码不自动修
→ 通过 → submit_recording_result
```
